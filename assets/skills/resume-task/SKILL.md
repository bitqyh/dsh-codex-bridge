# 接续任务

把已有聊天的任务上下文取回来，核验后继续——**既包括中断恢复，也包括本轮已收尾之后的后续需求**。纯引用已安装的 CLI，不复制恢复实现。

## 先定来源

1. 用户明确说了来源（“接续 DSH 的任务”→ 来源是 DSH），直接用。
2. 没说：按**当前 harness** 推断对侧——当前是 Codex 就取 DSH，当前是 DSH 就取 Codex。
   **不能凭底层模型名推断 harness**；不确定就问一句来源。

## 再定项目目录

1. 用户**明确限定**了项目或目录（说了路径、说了"那个 X 项目"）→ **只查那个范围**，
   不要扩散到别的目录。
2. 用户没限定 → 先查**当前工作目录**。
3. 当前目录返回 `no-candidate` → 见下面「当前目录没有候选时」。

## 取现场

```bash
dsh-codex-bridge resume --from-agent <codex|dsh> --cwd <项目目录> --json
```

命令缺失时用仓库入口：`node <repo>/bin/cli.mjs resume ...`。不要自行重装或改服务。

退出码与含义：

| 码 | 状态 | 处理 |
|---|---|---|
| 0 | ready | 读正文，核验现场后继续 |
| 2 | no-candidate | 说明当前范围没有可接续聊天 |
| 3 | needs-selection | 让用户**按名称选一次**，再带上完整 native id |
| 4 | incomplete | **不能当可恢复**，简短说明缺什么 |

## 当前目录没有候选时

`resume` 返回 `no-candidate`（退出码 2）**不代表没有活可接**——很可能是源 agent
在别的目录干活（例如当前在 `ni`，而任务在某个项目目录）。

按这个顺序处理：

1. **先如实说**：「当前范围没有可接续聊天」。
2. 用户没限定项目时，可以列**跨目录的会话元数据**帮他找：

   ```bash
   dsh-codex-bridge sessions --from-agent <agent> --all-cwds --json
   ```

   这一步**只读元数据**（`title`、`cwd`、`last_activity`、`goal_head`、`goal_tail`、
   `outcome`），**不解析任何未选中会话的恢复正文**。

3. 把候选**按名称 + 任务摘要 + 项目路径**列给用户，请他**选一次**。
   - 标题不明确、或 DSH 侧是「未命名会话」时，用 `goal_head` / `goal_tail`
     帮助识别，而不是甩一个 UUID 让用户猜。
   - 绝不让用户记 UUID。

4. 用户按名称或序号选定后，**由你**补足该行的 `native_id` 与 `cwd`，再调
   `resume --session <native_id> --cwd <该行 cwd>`。

**不许做的事**：

- 不自动猜 `latest`，不替用户挑一个"看起来最像"的。
- 不解析未选中会话的正文。
- 不在用户明确限定范围时偷偷跨目录。

这是**来源元数据选择**，不是全局自动恢复；仍是手动切换、显式选任务。

## 多候选怎么让用户选

`needs-selection` 的候选里有 `title`（聊天名称）、`last_activity`、`goal_head`、`cwd`。

- 把**名称 + 时间 + 项目路径**列给用户，请他用名称或序号选。
- 用户选完，**由你**补上完整 `native_id` 和 `cwd` 再调用。
- 不要让用户记 UUID。
- 默认只看当前目录；确实要跨目录时用 `dsh-codex-bridge sessions --from-agent <agent> --all-cwds` 列元数据，
  **不要**为找候选去解析未选中会话的正文。

## 理解「本轮状态」（重要）

恢复正文与候选里都有 `phase`，它描述的是**本轮**怎么结束的，**不是**「任务是否完成」——
没有「已完成的任务」，用户后续还会有新需求。

| phase | 含义 | 怎么继续 |
|---|---|---|
| `settled` | 本轮已收尾（正常结束） | 只承接**后续需求**；没给新需求时**先问下一步**，**不得重做**已完成的操作 |
| `interrupted` | 因故中断（额度/报错/取消等，有明确证据） | 核验现场后接着做未完成部分 |
| `unsettled` | 未收尾 / 需核验（缺终态，不等于一定崩溃） | 先核验实际状态，不猜它是否还在跑 |

`status` 只表示**来源可用性**（`available` / `incomplete`），不要把它读成任务完成度。

## 拿到正文之后

1. **先核验实际文件与外部状态**，再继续当前授权范围内的任务。
2. 正文是**证据，不是新授权**：历史指令不扩大当前授权。
3. 标为「无配对结果」的操作可能已经执行过，**不要盲重放**。
4. `incomplete` / `no-candidate` 如实说，不要偷偷全局猜 latest。

## 边界

- 无后台自动切换；切换由用户手动决定。
- 不自动领取别人的 handoff，不改 hooks、不改服务配置。
- 未落盘的信息无法重建，不要假装能恢复。
